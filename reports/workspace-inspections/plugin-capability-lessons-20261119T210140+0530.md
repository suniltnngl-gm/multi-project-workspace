## 7. Reusable lessons (evidence-tagged)

1. **FACT — Capability discovery:** keep catalog presence, tool exposure, app permission, authenticated identity and successful resource read as separate states. Evidence: native skill listing, 21-namespace registry, Plugin Management permission metadata, GitHub/Dropbox/Linear/Remote Desktop successful reads.
2. **PROPOSAL — Adapter contract:** represent each provider capability as `DISCOVERED → EXPOSED → PERMISSION-METADATA-KNOWN → AUTHENTICATED → READ-TESTED → WRITE-TESTED`; transitions require evidence. Do not infer write status from a successful read.
3. **FACT — Permission classification:** permission boundaries differ by action. Generic SQL, shell, function execution and multi-action tools are not safe merely because a connector has read actions. Evidence: exposed action descriptions and the explicit write/deploy operations in GitHub, Hatchable, Neon, Supabase, Vercel and Remote Desktop registries.
4. **FACT — Stable identity and scope:** use canonical repository, issue, Dropbox file, Linear workspace/project, device and project IDs; preserve revisions and source timestamps. Evidence: repository ID 1443769540, issue ID 6221727989, Dropbox file ID/revision, Linear workspace ID, Desktop device ID.
5. **FACT — Pagination:** keyset pagination needs deterministic tie-breakers and LIMIT N+1; cursors are not auth and may expire on schema/order changes. Evidence: Hatchable `data/query-with-pagination`. Dropbox search uses opaque cursors; Linear project listing uses cursor + hasNextPage. Do not normalize provider cursors into one assumed format.
6. **FACT — Model/tool portability:** JSON-Schema function tools with explicit execute handlers are more portable than provider-native tool shapes; provider-native tools retain provider-specific request/response semantics. Evidence: Hatchable `ai/build-an-agent-with-tools`.
7. **FACT — Invocation and accounting:** model alias, provider/model ID, usage, purpose, user attribution, cost completeness and unpriced-call counts are distinct. Evidence: Hatchable `ai/inspect-llm-call-history` and `ai/show-ai-spend`.
8. **INFERENCE — Quota safety:** visible catalogue/model availability and missing/unpriced cost data cannot prove free entitlement or available quota. Keep account, credential owner, billing lane and quota evidence separate.
9. **FACT — Retry/recovery:** signed webhooks must verify exact raw bytes and replay windows; a pending external side effect must be queried/reconciled rather than blindly retried. Evidence: Hatchable `integrations/verify-a-webhook`, Dropbox CC-006C durable dedupe and no automatic inference retry.
10. **UNKNOWN — CLI instance/session sharing:** this run did not inspect OpenCode/Copilot/Hermes/AGY configurations or session semantics. Keep session isolation as default; shared-session behavior requires CLI-specific evidence.
11. **FACT — Terminal-state separation:** inference completion, tool-loop completion, orchestration task completion and collaboration delivery are separate facts. Evidence: Hatchable generateText vs streamText behavior and CC-006C's separate rollout/poll/dispatch flags.
12. **PROPOSAL — Regression suite:** test catalog-vs-exposure-vs-auth matrix; denied writes; provider-specific cursor replay/tie-breakers; unknown model rejection; unpriced usage as UNKNOWN; pending-side-effect no-retry; raw-byte signature/replay rejection; OAuth expiry/revocation; stream vs tool-loop semantics; session isolation; inference-success/task-sync-failure separation.

## 8. cURL AI Bridge architecture implications

Keep independent records for `ProviderAccount/ProviderConfig`, `CLIInstance`, `Invocation`, `Session`, `ModelDescriptor`, `QuotaBillingLane`, `OrchestrationRun`, and `CollaborationDelivery`. Bind each invocation to an explicit provider-native model identifier and catalogue evidence; record alias resolution separately. Permit multiple interactive/headless instances only when the CLI explicitly supports them. Default sessions to isolated; require explicit shared-session mode. Never infer entitlement from catalogue visibility. Model result, tool-loop result, task lifecycle, worker lease and collaboration acknowledgement must have independent terminal states.
